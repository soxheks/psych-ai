# 结构化学业压力陪伴与今日行动卡

## 目标

面向竞赛、科研、代码调试、绩点、备考和学业受挫场景，将一次泛化聊天变成可理解、可继续的陪伴流程。该功能不做诊断或治疗承诺，重点帮助学生表达压力、区分担心与事实、识别可控部分，并选择一个十分钟左右的小行动。

## 对话流程

1. 倾听此刻：初始状态，接住用户当前表达。
2. 看清压力：共情后用两到三个不同的探索问题梳理事实和担心，每轮最多一个。两个问题得到回应且已有具体情境时结束探索；若信息仍少，再补一个问题。
3. 找到可控：回应两到三个探索问题后，根据已有学业困扰主动衔接到一个可选的“今日行动卡”。第三个回应仍说不清时不无限追问，基于已知事实给出保守的小步骤，不猜测未知原因。用户也可以提前主动求助。先说明当前困难与小步骤的联系，不要求用户说“我该怎么做”，也不把展示建议当成同意行动。
4. 迈出一步：用户从三个候选步骤中选择一个，卡片立即展开行动陪伴入口。用户可以标记“开始这一步”，或通过“我完成了、我卡住了、这一步太难”把状态和已选行动自动带回 AI；后续回复分别进行进展复盘、阻碍澄清或重新缩小步骤。

危机表达优先进入结构化安全支持流程，不调用普通 AI、不生成行动卡，也不返回学业任务。页面引导用户确认是否独处、是否有立即危险，并连接能够到场的真人支持。

用户可随时选择“先陪我待一会儿”、“换个轻松话题”或“结束本次对话”。这些按钮通过独立的 `conversation_intent` 字段传递，由服务端给出不追问的稳定回应，不依赖模型猜测。

倾听阶段新增“一起梳理”入口，通过普通用户表达恢复澄清，不自动同意或完成行动。有未发送草稿时不会覆盖草稿。即使恢复了旧版保存的倾听偏好，也可以明确退出暂停；无需清空聊天。

一般性的“先陪我聊聊/说说”不再保存为禁止推进的长期偏好。明确的“只想倾诉、不想建议、先待一会儿”仍持续有效。普通疲惫/难受首次表达可先倾听，收到陪伴后继续表达时允许边安抚边澄清；补充具体阻碍时可给可选步骤，不要求先完全平静。强烈失控表达仍优先倾听，危机仍走独立安全分支。“不知道怎么办”等模糊状态不直接判成已经具备行动信息；“卡在公式推导”等简短具体补充不因字数不足而遗漏。阶段不按固定轮数推进，第四步的完成仍需要明确的用户反馈。

`core/conversation.py` 使用有限要点中的 `answered` 问答记录去重计数，并结合用户原话判断信息是否够用。单纯聊满两轮、重复提问和未回应的问题不计作完成探索。回应两个不同问题且任一回应给出具体阻碍、担忧或时间等信息时，可主动提供可选行动；回应三个后允许基于有限信息给建议。“对”等简短回应可以承接前文，未知原因仍保留为未知。第一句困扰、纠正、尚未说完和当前澄清问题不直接发卡。未准备好、强烈难受或持续的倾诉偏好优先于主动过渡；个人话题、诊断边界和危机流程也仍优先。已选和完成状态单独保留，不被主动建议重置。

服务端支持“怎么办”“有没有更轻一点的办法”“不知道从哪里开始”等自然求助表达，并区分“不知道从哪里开始”和“不想开始”。主动过渡不修改用户的陪伴偏好，不自动选择行动，不产生行动完成统计。卡片说明可选择暂时不做，用户可用既有倾诉按钮暂停。这里是基于上下文和中文表达线索的可测试规则，不是完整语义理解；尚未覆盖的说法、跨话题和实际模型衔接质量仍需真实试用验证。

用户最新一句中的明确意愿优先于旧偏好，并按语句先后解析。例如先说“不想听建议”、随后说“现在愿意试一个小步骤”会进入行动阶段；如果一句话最后又说“不过先别给建议”，仍留在倾听阶段。普通文本“今天先聊到这里”也会稳定结束对话，不依赖模型猜测。

## 数据与隐私

- 会话要点新增有限的 `topic` 枚举（`personal` / `academic`），用于保留明确的非学业话题和返回学业的意愿；不新增数据库记录。用户谈分手等非学业困扰时，不沿用旧学习行动约束，撤下未选择的学业卡片。后续短句追问仍保持该话题，明确返回学业或点击学业场景开场白后恢复学业流程。
- `presented_actions` 独立记录至多 12 个已经展示的卡片步骤，每项最多 180 字；它不表示用户已选择、已开始或已完成。记录只随有限会话要点往返，沿用主动开启才本地保存的规则，不写入数据库或匿名统计。流式中断且未交付卡片时不记录；卡片被替换或撤下时清理记录，恢复本地进度时只保留实际恢复的已选步骤。

- 默认不持久化对话。用户主动勾选后，浏览器才在本设备 `localStorage` 中保存最近六段对话、有限会话要点、当前阶段、压力评分与行动状态；可随时一键清除。
- 外部模型每次接收最近六条消息，每条最多 500 字符，只允许 `user` 和 `assistant` 角色。超长消息保留首尾并标注中间省略，避免末尾纠正被直接截掉；预算不变。额外要点包括最初困扰（240 字符）、最多八条原话摘录、十二个已问问题、六组问题与用户回应（每项最多 180 字符）及当前陪伴偏好。它是原话提取，不推断经历或诊断；“已回应”不等于已解决。
- 会话要点默认仅在当前页面内存中保存，经接口处理后返回浏览器，不写入 Django Session 或数据库，不进入匿名统计。刷新且未开启本地保存时清除；进入安全模式同时清除普通对话历史与要点。外部模型会收到这些有限要点，页面已说明。
- 危机安全支持内容永不写入本地进度，进入安全模式时会清除已保存的普通对话快照。
- 只有用户另行勾选匿名贡献后，服务端才记录场景、前后压力、是否完成行动，以及“被理解、建议可执行、帮助程度、再次使用意愿”四项 1–5 分评价和最多 300 字的可选建议；数据表不包含对话文本字段，用户取消勾选后删除本次记录。
- 首页提供 `?trial=1` 自愿体验入口。试用模式在首次发送前邀请用户选择压力分数，也允许跳过；普通结束与完成行动都能出现后测和反馈，不把样本限制在完成行动的用户。服务端要求每次写入显式携带同意状态，绑定当前浏览器会话，并禁止结束后的前测回填或篡改。
- 完成小结默认只展示后测和一项“是否有帮助”；其余三项评分与文字建议折叠，减少结束时的问卷负担。首页和后台分别展示完整配对、缺失前后测、降低/不变/上升，并明确这是自愿记录的当次主观感受，不代表独立人数、临床效果或因果关系。
- 匿名贡献开关默认关闭，只在当前浏览器页面会话内保持。完成行动后，页面会直接展示评价区和独立同意开关；未同意时填写内容只停留在当前页面。
- 配置的外部模型仍会处理发送给它的内容，部署和试用材料中应如实说明模型服务方。

## 模型与降级

- 明确用文字报告当前已选步骤完成时，服务端在调用模型前同步 `action_status`，前端同步行动卡、第四步和完成小结。条件句、疑问、部分完成、否定完成和引述不作为完成依据；未选择步骤或当前为非学业话题时不推断旧行动完成。
- 风险识别按分句检查，仅排除完整且明确的风险否定句，继续检查其余分句。否定后出现控制不住或无法保证等不确定表达仍进入安全流程；已有安全状态不会被一句否认自动解除。这些规则只覆盖明确表达，不是完整语义理解或临床评估。

- 豆包、Gemini 和 Ollama 共用阶段提示词，模型只生成对话文字，阶段状态和行动卡由服务端控制。
- 模型上下文使用原生多轮角色，不再把历史全部拼入最后一条用户消息：豆包/Ollama 使用 `user` / `assistant`，Gemini 对应 `user` / `model`。最终用户消息单独提供最新表达、有限要点及当前阶段信息。只接受允许的历史角色，不允许客户端历史插入系统消息；这不代表客户端提交的内容已被验证真实。
- 场景匹配以有限的明确自述规则纠正侧栏默认值，例如“我在备考”优先于旧竞赛标签；模型与行动卡使用同一个解析结果。引用、假设和多个场景不强猜，无法识别时沿用合法侧栏场景。已选标准行动按其所属场景保留，不替用户换行动；不增加保存字段，不修改用户选择的侧栏或匿名记录场景。它不是语义分类模型，歧义仍需要澄清。
- 提示词区分事实、担忧和助手猜测，禁止把走神自动推断成备考、成绩差或疾病；要求遵守用户时间、资源与意愿限制，不编造统计或医学结论。问句过滤保留原文/包含关系去重，取消无序汉字重合率判断，避免“压力变大/变小”等不同问题被误删。语义改写的重复不保证完全拦截。
- 豆包使用流式返回，服务端先积累一个完整短句并检查重复问题、行动状态冲突、倾诉阶段催促及重复标点，然后发送 NDJSON 增量。最后一个句末边界等待后续字符或流结束确认，以处理跨块标点。缺少句末标点时需要等到回复结束，不能保证每个 token 即时显示。
- 同一次回复最多保留一个新问题。已问问题同时检查最近消息和有限要点；已完成行动不得重新催开始。普通 JSON 与流式响应共用检查器。结束事件的 `reply` 严格等于所有增量拼接，前端不再整段替换；语音使用同一份检查后的文字。
- 若模型在已有检查后短句发出后中断，保留这些短句、丢弃未完成尾句，返回明确中断状态并保留用户输入供重试；不会混入其他模型续写。首句尚未发出时允许降级为基础陪伴。Gemini、Ollama 继续使用单次模型返回，兼容相同短句检查协议。
- 等待首段回复时会依次显示“理解此刻重点、回看对话重点、整理合适回应、需要多一点时间”四级低干扰提示；收到首段文字或请求结束后立即停止定时提示。
- 用户选定的行动同时以独立的 `selected_action` 字段传递，并在模型提示词中明确标注；回复必须围绕该具体行动，不再依赖模型从自然语言历史中猜测。页面状态栏会显示豆包、Gemini、本地 AI 或基础陪伴模式，方便现场确认实际服务来源。
- 行动进度同时以 `action_status` 传递，取值为已选择、已开始、已完成、卡住或正在缩小。完成状态会持续到后续对话，模型不得再次催促用户开始同一步；服务端会拦截与状态矛盾的回复并转为完成后的复盘。
- 服务端校验行动阶段回复；只有近期助手消息和独立卡片记录均未交代所选步骤时，才补充一次行动锚点，不再每轮强制重念整个步骤。
- 服务端统一清理行动锚点和模型回复中的重复句号、问号、感叹号等标点，避免 `。”。` 这类拼接问题。
- 行动卡采用经过人工限定的六类学业场景步骤，每张卡有一个默认步骤和两个可替换步骤，避免模型生成过大或不合适的任务。
- 候选行动统一由 `core/actions.py` 生成，同一份步骤进入模型提示和行动卡；对话文字负责具体解释，不再无条件追加“这一小步是……”固定段落。卡片展示记录独立于对话文字，近期消息截断后也不依赖复述步骤防止重复发卡。过滤编号清单和卡片整段原文，保留自然表达的具体做法；全部文字被过滤时提供简短支持，步骤仍在卡片中。建议的语义一致性仍需真实模型验收。
- 共情不再固定为每轮“复述事实＋猜测担心”。“对、是的”等简短确认结合上一问处理，不等同于同意行动；允许一个新的具体探索问题，不再一律删除确认后的全部问句，仍过滤重复问题与“对吧、是不是”等再次确认。普通困扰首轮的提示词要求接住情绪后给出容易回应的具体入口；明确暂停、纠正及完成后缓解的边界不变。直接求助时提示模型说明同一动作的具体例子、范围或执行细节。完整短句发送前还会去掉近期助手消息中逐字相同（忽略常见标点）的重复句。语义改写的重复和探索问题的质量仍需真实模型验证，并非确定性保证。
- 明确纠正理解的当轮不再提问，包括以句号结束的“对吧”。提示词要求最新纠正优先于旧要点和助手推测，但不把纠正扩展成永久性格。完成后的缓解表达不再触发固定回复覆盖模型输出；保留具体回应，只过滤重复追问和重新催开始。基础陪伴在用户明确提及有效方法时引用这条反馈，不再说“不需要找解释”。
- `core/medical.py` 为明确的诊断、排除疾病及用药请求提供非诊断边界回复（`provider=guided`），不调用模型、不发学业卡；当前危机和已有安全状态仍优先。普通提及已获得的诊断不等于请求重新诊断。提示词也禁止“不能诊断，但更像压力”的归因。识别采用有限中文规则，并不覆盖全部隐喻或变体；普通自由对话的医学措辞仍需持续抽查。评估边界参考 [NICE NG222 1.2.6–1.2.7](https://www.nice.org.uk/guidance/NG222/chapter/recommendations)：不能仅据有限症状判断，需要综合评估；本项目不执行临床评估。
- 模型不可用时，规则回复仍按同一阶段运行并正常提供行动卡。

## 评分对应

- 创新性：围绕高校学业压力形成“情绪表达—压力澄清—可控识别—微行动—复盘”闭环。
- AI 技术应用：模型提示词显式感知陪伴阶段和有限上下文，服务端负责流程约束、角色过滤、安全分流与降级。
- 项目实施：前后端状态协议、响应式行动卡、无障碍阶段标记和自动化回归测试均已实现。
- 应用成效：首页只展示经用户知情同意产生的真实聚合结果，包括行动完成率、压力下降比例与平均变化；后台可核验体验评分和可选建议。无数据时显示“待积累”，不伪造样本或作医疗效果声明。

## 后台效果分析

- 超级管理员进入“匿名成效记录”后，可按场景、行动完成状态和日期筛选；页面顶部统计卡与当前筛选同步，展示样本数、行动完成率、有效前后测、压力缓解比例，以及四项体验评分均值。
- “导出当前筛选 CSV”会导出当前筛选结果，字段仅包含匿名事件 ID、场景、前后压力、行动状态、四项评分和可选建议，不包含任何对话原文。
- CSV 使用 UTF-8 BOM 方便 Excel 直接打开，并对以 `= + - @` 开头的建议做公式注入转义。

## 验收记录

### 2026-10-06 两到三个问题后的主动推进（本地验收）

- 根据用户反馈，普通学业困扰在回应两个不同探索问题且已有具体信息后进入第三步；信息不足时最多补一个探索问题，第三个回应后使用已知事实提出可选小步骤。简短确认、有限历史和会话要点均参与判断，不需要主动问方法。
- 模型提示同步收到已回应问题数和探索预算；基础陪伴模式按不同问题继续梳理。明确暂停、尚未说完、纠正、强烈失控、医疗边界、危机支持和真实行动完成条件保持优先。
- 完整 145 项 Django 测试通过，新增 7 项覆盖单问不提前推进、两问加简短确认、三问仍不确定、简短困扰不遗漏、重复/未回答问题不计数、有限历史及用户边界、基础陪伴普通与流式完整流程。
- 本地真实接口浏览器短流程在 1440/390px 通过：两个不同问题得到回应后主动进入第三步，流式文字与最终回复一致，选定行动后明确报告完成，第四步和小结同步。没有默认保存或提交匿名成效；记录位于 `output/question-budget-2026-10-06/`。本地使用基础陪伴模式，这次短流程未中断，但不据此认定此前长对话中断已解决。尚未上传部署，真实豆包与线上验收仍待进行；合成测试不属于匿名成效数据。
