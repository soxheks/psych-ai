# 结构化学业压力陪伴与今日行动卡

## 目标

面向竞赛、科研、代码调试、绩点、备考和学业受挫场景，将一次泛化聊天变成可理解、可继续的陪伴流程。该功能不做诊断或治疗承诺，重点帮助学生表达压力、区分担心与事实、识别可控部分，并选择一个十分钟左右的小行动。

## 对话流程

1. 倾听此刻：初始状态，接住用户当前表达。
2. 看清压力：共情后梳理事实和担心，必要时最多提出一个未问过的问题，不要求每轮追问。
3. 找到可控：用户明确希望获得建议、开始行动或缩小已选步骤时，显示场景专属“今日行动卡”。
4. 迈出一步：用户从三个候选步骤中选择一个，卡片立即展开行动陪伴入口。用户可以标记“开始这一步”，或通过“我完成了、我卡住了、这一步太难”把状态和已选行动自动带回 AI；后续回复分别进行进展复盘、阻碍澄清或重新缩小步骤。

危机表达优先进入结构化安全支持流程，不调用普通 AI、不生成行动卡，也不返回学业任务。页面引导用户确认是否独处、是否有立即危险，并连接能够到场的真人支持。

用户可随时选择“先陪我待一会儿”、“换个轻松话题”或“结束本次对话”。这些按钮通过独立的 `conversation_intent` 字段传递，由服务端给出不追问的稳定回应，不依赖模型猜测。

阶段不再按轮次自动推进。`core/conversation.py` 根据用户明确的倾诉、梳理和行动表达选择阶段；未准备好或强烈难受时优先倾听，选过行动和完成状态仍单独保留。倾诉偏好持续到用户明确改变意愿，普通担心不会在第二轮自动触发任务。服务端还会识别“我能控制的是……”和“我先花 10 分钟……”这类已经准备行动的自然表达，稳定进入行动卡，不依赖模型自行猜测。这里是可测试的规则路由，不是情绪诊断或完整语义分类，含糊和隐喻表达仍需要真实试用验证。

用户最新一句中的明确意愿优先于旧偏好，并按语句先后解析。例如先说“不想听建议”、随后说“现在愿意试一个小步骤”会进入行动阶段；如果一句话最后又说“不过先别给建议”，仍留在倾听阶段。普通文本“今天先聊到这里”也会稳定结束对话，不依赖模型猜测。

## 数据与隐私

- 默认不持久化对话。用户主动勾选后，浏览器才在本设备 `localStorage` 中保存最近六段对话、有限会话要点、当前阶段、压力评分与行动状态；可随时一键清除。
- 每次请求携带最近六条消息，每条截断到 500 字符，只允许 `user` 和 `assistant` 角色。额外要点包括最初困扰（240 字符）、最多八条原话摘录、十二个已问问题、六组问题与用户回应（每项最多 180 字符）及当前陪伴偏好。它是原话提取，不推断经历或诊断；“已回应”不等于已解决。
- 会话要点默认仅在当前页面内存中保存，经接口处理后返回浏览器，不写入 Django Session 或数据库，不进入匿名统计。刷新且未开启本地保存时清除；进入安全模式同时清除普通对话历史与要点。外部模型会收到这些有限要点，页面已说明。
- 危机安全支持内容永不写入本地进度，进入安全模式时会清除已保存的普通对话快照。
- 只有用户另行勾选匿名贡献后，服务端才记录场景、前后压力、是否完成行动，以及“被理解、建议可执行、帮助程度、再次使用意愿”四项 1–5 分评价和最多 300 字的可选建议；数据表不包含对话文本字段，用户取消勾选后删除本次记录。
- 首页提供 `?trial=1` 自愿体验入口。试用模式在首次发送前邀请用户选择压力分数，也允许跳过；普通结束与完成行动都能出现后测和反馈，不把样本限制在完成行动的用户。服务端要求每次写入显式携带同意状态，绑定当前浏览器会话，并禁止结束后的前测回填或篡改。
- 完成小结默认只展示后测和一项“是否有帮助”；其余三项评分与文字建议折叠，减少结束时的问卷负担。首页和后台分别展示完整配对、缺失前后测、降低/不变/上升，并明确这是自愿记录的当次主观感受，不代表独立人数、临床效果或因果关系。
- 匿名贡献开关默认关闭，只在当前浏览器页面会话内保持。完成行动后，页面会直接展示评价区和独立同意开关；未同意时填写内容只停留在当前页面。
- 配置的外部模型仍会处理发送给它的内容，部署和试用材料中应如实说明模型服务方。

## 模型与降级

- 豆包、Gemini 和 Ollama 共用阶段提示词，模型只生成对话文字，阶段状态和行动卡由服务端控制。
- 豆包使用流式返回，服务端先积累一个完整短句并检查重复问题、行动状态冲突、倾诉阶段催促及重复标点，然后发送 NDJSON 增量。最后一个句末边界等待后续字符或流结束确认，以处理跨块标点。缺少句末标点时需要等到回复结束，不能保证每个 token 即时显示。
- 同一次回复最多保留一个新问题。已问问题同时检查最近消息和有限要点；已完成行动不得重新催开始。普通 JSON 与流式响应共用检查器。结束事件的 `reply` 严格等于所有增量拼接，前端不再整段替换；语音使用同一份检查后的文字。
- 若模型在已有检查后短句发出后中断，保留这些短句、丢弃未完成尾句，返回明确中断状态并保留用户输入供重试；不会混入其他模型续写。首句尚未发出时允许降级为基础陪伴。Gemini、Ollama 继续使用单次模型返回，兼容相同短句检查协议。
- 等待首段回复时会依次显示“理解此刻重点、回看对话重点、整理合适回应、需要多一点时间”四级低干扰提示；收到首段文字或请求结束后立即停止定时提示。
- 用户选定的行动同时以独立的 `selected_action` 字段传递，并在模型提示词中明确标注；回复必须围绕该具体行动，不再依赖模型从自然语言历史中猜测。页面状态栏会显示豆包、Gemini、本地 AI 或基础陪伴模式，方便现场确认实际服务来源。
- 行动进度同时以 `action_status` 传递，取值为已选择、已开始、已完成、卡住或正在缩小。完成状态会持续到后续对话，模型不得再次催促用户开始同一步；服务端会拦截与状态矛盾的回复并转为完成后的复盘。
- 服务端校验行动阶段回复；只有近期助手消息尚未交代所选步骤时，才补充一次行动锚点，不再每轮强制重念整个步骤。
- 服务端统一清理行动锚点和模型回复中的重复句号、问号、感叹号等标点，避免 `。”。` 这类拼接问题。
- 行动卡采用经过人工限定的六类学业场景步骤，每张卡有一个默认步骤和两个可替换步骤，避免模型生成过大或不合适的任务。
- 候选行动统一由 `core/actions.py` 生成，同一份内容同时进入模型提示、可见回复和行动卡。首次展示时过滤编号清单并补上唯一候选动作；近期已展示同一动作时不再发卡或补写固定步骤，改为解释该动作。首次及后续解释均保留自然表达的具体做法，不再因“你可以”等措辞删掉整句。建议应围绕卡片的约束由提示词表达，规则无法完整判断建议的语义一致性，仍需真实模型对话验收。
- 共情不再固定为每轮“复述事实＋猜测担心”。“对、是的”等简短确认结合上一问处理，不等同于同意行动；直接求助时提示模型说明同一动作的具体例子、范围或执行细节。完整短句发送前还会去掉近期助手消息中逐字相同（忽略常见标点）的重复句，不用模糊相似度删除可能改变含义的纠正。语义改写的重复主要依赖提示词约束，并非确定性保证。
- 模型不可用时，规则回复仍按同一阶段运行并正常提供行动卡。

## 评分对应

- 创新性：围绕高校学业压力形成“情绪表达—压力澄清—可控识别—微行动—复盘”闭环。
- AI 技术应用：模型提示词显式感知陪伴阶段和有限上下文，服务端负责流程约束、角色过滤、安全分流与降级。
- 项目实施：前后端状态协议、响应式行动卡、无障碍阶段标记和自动化回归测试均已实现。
- 应用成效：首页只展示经用户知情同意产生的真实聚合结果，包括行动完成率、压力下降比例与平均变化；后台可核验体验评分和可选建议。无数据时显示“待积累”，不伪造样本或作医疗效果声明。

## 后台效果分析

- 超级管理员进入“匿名成效记录”后，可按场景、行动完成状态和日期筛选；页面顶部统计卡与当前筛选同步，展示样本数、行动完成率、有效前后测、压力缓解比例，以及四项体验评分均值。
- “导出当前筛选 CSV”会导出当前筛选结果，字段仅包含匿名事件 ID、场景、前后压力、行动状态、四项评分和可选建议，不包含任何对话原文。
- CSV 使用 UTF-8 BOM 方便 Excel 直接打开，并对以 `= + - @` 开头的建议做公式注入转义。
